## Normal startup

1. Open Ubuntu first from PowerShell:

   ```powershell
   wsl -d Ubuntu
   ```

2. In a separate PowerShell terminal, identify the receiver:

   ```powershell
   usbipd list
   ```

   The tested receiver is **NESDR SMArt v5**, USB `0bda:2838`, bus ID **1-2**. If its state is already `Attached`, leave it attached. Otherwise:

   ```powershell
   usbipd attach --wsl --busid 1-2
   ```

   USB bus IDs can change after moving ports. Use the receiver's actual bus ID from `usbipd list` if it differs.

3. In Ubuntu, use the managed services. `start` is safe to repeat while a service is already active:

   ```bash
   sudo systemctl start terrasatch-demo-radio.service terrasatch-simulator-gateway.service
   systemctl is-active terrasatch-demo-radio.service terrasatch-simulator-gateway.service terrasatch-simulator-runtime.service
   ```

   All three should report `active`. The gateway starts its existing isolated runtime service. No `--prepare`, `--qa`, package installation, or PX4 build is needed for normal use.

4. In PowerShell, check the existing private bridge task:

   ```powershell
   Get-ScheduledTask -TaskName 'TerraSatch Simulator Host' | Select-Object TaskName,State
   ```

   It should be `Running`. If it is stopped, start that same task:

   ```powershell
   Start-ScheduledTask -TaskName 'TerraSatch Simulator Host'
   ```

5. Open the production domain, sign in, and check **Simulator: Ready**. Keep one active demo workspace open. The simulator supports one active lease at a time; an extra preview can hold an unused preparation lease.

To watch reception in a terminal while the managed listener runs:

```bash
journalctl -u terrasatch-demo-radio.service -f
```

Ctrl+C closes this log viewer and leaves reception running. Successful input shows `radio.transcription.completed`, then HTTP `201 Created` and `radio.transmission.delivered`. The managed receiver uses the existing speech engine and optional place-name hints; they are not activation words.

If you specifically want a foreground listener, use this **instead of** the managed listener. Stop the service first so two processes do not compete for USB:

```bash
sudo systemctl stop terrasatch-demo-radio.service
sudo -u k3y10 env TERRASATCH_EDGE_CONFIG_DIR=/home/k3y10/.config/terrasatch-edge \
    TERRASATCH_EDGE_STATE_DIR=/home/k3y10/.local/state/terrasatch-edge \
    /opt/terrasatch-edge-0.2.4-venv/bin/terrasatch-edge radio start --channel 5 \
    --hotwords "Satchy, Flagstaff, Two Dogs, Alta, AvyTS, PyroTS, Slough Canyon"
```

When finished, press Ctrl+C and restore the managed listener:

```bash
sudo systemctl start terrasatch-demo-radio.service
```

## Two demonstrations

**AvyTS / radio:** Select Flagstaff / Two Dogs in the UAC Salt Lake context and one cell. Say:

> Satchy, log this snow report at Flagstaff. Survey the selected cell.

**PyroTS / Photon:** Select Slough Canyon and one cell. From the already verified Photon phone, send:

> Satchy, log this smoke report at Slough Canyon. Survey the selected cell.

For either input:

1. Click the new entry in **Field Activity**. Check the original transcript/message and Satchy's response.
2. Confirm the correct location and highlighted H3 cell. Resolve any uncertain transcription or place before proceeding.
3. Click **Review Quick Survey**. Allow the cached simulator to become ready at the selected terrain coordinates.
4. Review the exact cell, route, altitude, modelled RGB payload and revision. Check the review box, then click **Approve & run simulation**.
5. Show **Recon Results** after landing: actual flight outcome, modelled coverage, source-backed context, follow-up and the exact mission's integrity status.

Prepare the proposal when ready to review it: proposals expire after about two minutes, and incoming reports expire for new dispatch after 30 minutes. A fresh report is preferable to attempting to reuse an expired one. A spoken request alone never approves or dispatches a mission.

The final October 27 radio example took **102.9 seconds in flight**, **2m51s from cell confirmation to landing**, and **3m56s from reception including time before operator confirmation**. The verified-phone example flew for **119.5 seconds**. Cold startup, network conditions and review time can vary. Allow the first terrain/session preparation time in the presentation.

Coverage is an RGB footprint model derived from real PX4 positions. It is not camera imagery or a snow-stability, buried-layer, snow-depth, heat or containment measurement. UAC historical material is dated; live forecasts/weather and incident sources may change or report unavailable data tomorrow.

## Short recovery checks

| Symptom | Check |
| --- | --- |
| No radio entry | Receiver attached to Ubuntu; service active; handheld on the tested channel; check the listener log and correct device/site identity above. |
| Simulator unavailable | PC awake/online, managed gateway/runtime active, Windows bridge task running; then allow the app's status check to refresh. |
| Input received but no survey | Review the actual words and processing status. Ambiguous traffic stays a report until supported intent and cells are confirmed. |
| Proposal/report expired | Receive a fresh report and prepare a fresh reviewed proposal. |
| Recording fallback needed | Use **Replay this captured run** on the matching completed mission and call it a recorded simulation. Keep its original route, time and source attribution. |

The final mission's recording and 100% modelled coverage were reopened through the authenticated production app after a grounded simulator service restart. Earlier telemetry overwritten before the recording fix cannot be recovered. Never restart a runtime during an active survey to troubleshoot the UI.

Leave production on the tested frontend/API releases for the event. The accompanying source snapshot is a backup, not a tomorrow-morning installation step.
